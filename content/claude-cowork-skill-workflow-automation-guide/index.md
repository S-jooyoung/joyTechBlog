안녕하세요, 이번에는 개발자뿐만 아니라 비개발자분들에게도 유용한 글을 포스팅해보려 합니다.

실제로 제가 다니고 있는 아모트래블에서도 그룹 투어 모집을 위해 인플루언서 리서치에 매주 1~2시간 정도를 소비하고 있었거든요. 인스타, 유튜브, 블로그를 돌아다니면서 하나하나 시트에 정리하는 작업이었는데, 리스트가 커질수록 한계가 분명했어요. SaaS 도구도 써봤지만 우리 타겟에 딱 맞추긴 어려웠고요.

그래서 Claude Cowork의 스킬이라는 기능으로 이 작업을 자동화해봤는데, 1~2시간이 약 5분으로 줄었어요. 결과만 확인하면 되는 수준이 된 거죠. 그 과정에서 깨달은 게 있어요 — 진짜 자동화는 프롬프트를 잘 쓰는 게 아니라, **스킬을 만들어놓고 계속 키우는 것**이라는 걸요.

> 이번 글에서는 비개발자도 따라할 수 있도록, 스킬 하나를 만들고 → 커넥터로 확장하고 → 실전에서 키워나가는 전체 과정을 공유합니다.

## 1. "기능은 다 알겠는데, 어떻게 조합하는 건데?"

Claude Cowork 소개글은 이미 많아요. 스킬이 뭔지, 커넥터가 뭔지, Chrome 연동이 뭔지 — 기능 하나하나를 설명하는 콘텐츠는 넘쳐나죠. 그런데 막상 써보려고 하면 이런 의문이 들더라고요.

**이 기능들을 어떻게 조합해서 하나의 업무 파이프라인을 만드는 거지?**

스킬 따로, 커넥터 따로, Chrome 따로 설명하면 감이 잘 안 와요. 실제로 하나의 업무를 자동화하려면 이것들이 어떻게 엮이는지가 중요한데, 그 조합 사례는 찾기 어려웠거든요.

그래서 이 글에서는 기능 소개가 아니라 **기능들의 조합**을 보여드리려 합니다. 제가 실제로 운영 중인 인플루언서 리서치 스킬을 예시로, 스킬 → 커넥터 → Chrome → 플러그인 → 스케줄링까지 하나의 파이프라인이 어떻게 완성되는지 처음부터 끝까지 공유할게요.

## 2. 먼저, 완성된 자동화의 전체 그림

구체적인 설정 방법에 들어가기 전에, 전체 그림부터 보여드릴게요.

### 배경

아모트래블에서는 그룹 투어 모집을 위해 인플루언서를 매주 리서치하고 있었어요. 인스타그램, 유튜브, 블로그를 하나하나 돌아다니면서 팔로워 수, 콘텐츠 성격, 협업 이력을 확인하고, 구글 시트에 정리하는 작업이었거든요. 리스트가 50명, 100명으로 커지면서 1~2시간은 기본이었어요.

물론 인플루언서 마케팅 SaaS도 있어요. 그런데 우리가 찾는 건 단순히 팔로워 수가 높은 인플루언서가 아니라, **여행 그룹 투어에 관심 있는 마이크로 인플루언서**였거든요. 기존 SaaS의 필터로는 이 타겟을 정확히 잡기 어려웠어요.

그래서 개발자인 제가 Cowork 스킬을 하나 만들어봤습니다.

### Before / After

| 항목 | Before (수동 리서치) | After (Cowork 스킬) |
| --- | --- | --- |
| **소요 시간** | 1~2시간 | ~5분 (결과 확인만) |
| **리서치 범위** | 사람이 떠올린 키워드만 | 키워드 조합 자동 확장 |
| **중복 체크** | 시트에서 눈으로 확인 | Google Sheets 커넥터가 자동 체크 |
| **결과 저장** | 수동 복붙 | 시트에 자동 등록 |
| **실행 주기** | 기억나면 | 매주 월요일 9시 자동 실행 |

사실상 사람이 하는 일은 "결과를 훑어보고 괜찮은 사람에게 DM이나 메일 보내기"만 남았어요. 사실 이것조차도 자동화가 가능하고요.

### 전체 파이프라인

```
[스킬 실행] → 키워드 기반 인플루언서 검색
     ↓
[Chrome 연동] → 프로필 방문, 최신 콘텐츠 확인
     ↓
[커넥터: Google Sheets] → 기존 리스트와 중복 체크
     ↓
[커넥터: Google Sheets] → 신규 인플루언서 자동 등록
     (Google Sheets 대신 Notion, monday.com 등 커넥터만 바꾸면 OK)
     ↓
[스케줄링] → 매주 월요일 9시 자동 반복
```

이 파이프라인은 인플루언서 리서치뿐 아니라 다른 유스케이스에도 응용할 수 있어요. 채용 후보자 리서치, 영업 리드 발굴, BD 파트너 탐색 — 구조는 똑같거든요. **검색 → 검증 → 중복 체크 → 등록 → 반복**이라는 패턴은 대부분의 반복 리서치에 적용됩니다.

참고로 저는 Google Sheets를 예시로 썼지만, 여러분 팀이 Notion을 쓴다면 Notion 커넥터를, monday.com을 쓴다면 monday.com 커넥터를 연결하면 돼요. 파이프라인 구조는 그대로고, 커넥터만 바꿔 끼우면 됩니다.

## 3. 스킬 크리에이터 — 대화로 만드는 업무 자동화 도구

스킬은 Cowork의 핵심이에요. 프롬프트를 매번 새로 쓰는 대신, **반복 업무를 하나의 도구로 저장**해두는 거예요. 한번 만들어두면 사이드바에서 클릭하거나 채팅창에서 바로 호출할 수 있고, 다른 사람과 공유도 되고, 스케줄링도 걸 수 있어요.

### ① 스킬 크리에이터 켜기

두 가지 방법이 있어요.

**방법 1:** 왼쪽 사이드바에서 **사용자 지정 → 스킬 → + 버튼 → Claude와 함께 창작하기**를 클릭하면 돼요.

**방법 2:** 대화창에 `/create-skill`을 입력하고 바로 원하는 스킬을 설명하면 됩니다. 더 빠르죠.

### ② Claude에게 말하기

스킬 크리에이터가 켜지면 Claude가 "어떤 스킬을 만들까요?"라고 물어봐요. 이때 아래 프롬프트를 복붙하면 됩니다.

**범용 프롬프트:**

```
나는 매주 반복하는 [업무명] 작업을 자동화하고 싶어.
현재는 [현재 방식]으로 하고 있는데, [문제점]이 있어.
이 작업을 스킬로 만들어줘.

입력: [사용자가 제공할 정보]
처리: [스킬이 해야 할 단계들]
출력: [최종 결과물 형태]
규칙: [반드시 지켜야 할 조건들]
```

유스케이스별로 대괄호만 채우면 돼요.

**인플루언서 리서치 예시:**

```
나는 매주 반복하는 인플루언서 리서치 작업을 자동화하고 싶어.
현재는 인스타/유튜브를 직접 검색하면서 스프레드시트에 정리하는데,
1~2시간 걸리고 중복 체크도 놓치는 경우가 있어.

입력: 검색 키워드 (예: "제주 여행", "그룹 투어")
처리: 키워드 조합으로 인플루언서 검색 → 팔로워/콘텐츠 확인 → 중복 체크 → 시트 등록
출력: Google Sheets에 이름, 핸들, 팔로워 수, 최근 콘텐츠 요약이 정리된 리스트
규칙: 팔로워 1천~5만 마이크로 인플루언서만, 최근 3개월 내 여행 콘텐츠가 있는 계정만
```

**채용 리서치 예시:**

```
입력: 채용 포지션 + 기술 스택
처리: LinkedIn/GitHub 검색 → 이력 확인 → 중복 체크 → 시트 등록
출력: 후보자 이름, 프로필 URL, 주요 경력, 기술 스택 매칭도
규칙: 경력 3년 이상, 해당 기술 스택 실무 경험 필수
```

**영업 리드 발굴 예시:**

```
입력: 타겟 산업 + 기업 규모
처리: 기업 검색 → 담당자 확인 → CRM 중복 체크 → 시트 등록
출력: 기업명, 담당자명, 연락처, 기업 규모, 산업 분류
규칙: 직원 수 50~500명, 최근 6개월 내 관련 뉴스가 있는 기업만
```

### ③ Claude 질문에 답하기

프롬프트를 입력하면 Claude가 세부 사항을 물어봐요. 입력값의 형식, 처리 과정의 세부 단계, 출력물의 컬럼 구조, 예외 상황 처리 규칙 — 이런 질문들이에요. 3~5개 정도의 질문에 답하면 스킬 구조가 완성됩니다.

이 과정이 중요한 이유가 있어요. Claude가 질문하는 항목들이 곧 **스킬의 규칙**이 되거든요. "팔로워 수 기준이 뭐예요?"라는 질문에 "1천~5만"이라고 답하면, 그게 스킬 규칙으로 저장돼요. 나중에 스킬을 실행하면 이 규칙에 맞는 결과만 나오는 거죠.

### ④ 완성된 스킬 설치하기

질문이 끝나면 Claude가 스킬을 생성하고, **Install** 버튼이 나타납니다. 클릭하면 왼쪽 사이드바의 Skills 탭에 저장돼요. 이후부터는 사이드바에서 클릭하거나, 채팅창에서 스킬 이름을 불러서 바로 실행할 수 있어요.

### ⑤ 아이디어 탭 활용하기

여기서 팁 하나. 스킬을 처음부터 직접 만들기 부담스럽다면 **아이디어 탭**을 먼저 둘러보세요.

Cowork 사이드바의 Ideas 탭에는 다른 사람들이 이미 만들어둔 스킬 아이디어와 워크플로우 템플릿이 올라와 있어요. "뭘 자동화할지 모르겠다"면 여기서 영감을 얻을 수 있고, 마음에 드는 아이디어가 있으면 바로 스킬로 만들 수도 있어요.

저도 인플루언서 리서치 스킬을 만들기 전에 아이디어 탭에서 비슷한 리서치 자동화 사례를 참고했거든요. 거기서 힌트를 얻어서 스킬 크리에이터에게 더 구체적으로 설명할 수 있었어요.

### 핵심: 처음부터 완벽하게 만들지 마세요

스킬을 만들 때 가장 중요한 마인드셋이에요. 처음부터 모든 예외 상황을 고려하고 완벽한 규칙을 짜려고 하면, 스킬을 만드는 것 자체가 업무가 돼버리거든요.

일단 기본 동작만 되게 만들고 돌려보세요. 결과를 보면서 "아, 이건 빠졌네", "이 규칙은 추가해야겠다" 하고 하나씩 고쳐나가는 게 훨씬 효과적이에요. 이 이야기는 섹션 8에서 더 자세히 다룰게요.

## 4. 커넥터 — 스킬의 손발을 만들어주는 외부 서비스 연결

스킬만으로도 리서치 자체는 가능해요. 하지만 결과를 구글 시트에 자동으로 저장하거나, 기존 리스트와 중복을 체크하려면 **커넥터**가 필요합니다.

커넥터는 Cowork가 외부 서비스에 접근할 수 있게 해주는 다리예요. Google Sheets, Notion, Slack, Gmail 등 다양한 서비스를 연결할 수 있어요.

### 커넥터 연결하기

왼쪽 사이드바에서 **사용자 지정 → 커넥터 → + 버튼 → 커넥터 둘러보기**를 클릭하면 연결할 수 있는 커넥터 목록이 나와요. Google Sheets, Notion, Slack 등 자주 쓰는 서비스는 대부분 있어요.

연결 방법도 간단합니다.

| 단계 | 할 일 | 소요 시간 |
| --- | --- | --- |
| 1 | 커넥터 둘러보기에서 서비스 선택 | 10초 |
| 2 | OAuth 인증 (로그인 팝업) | 30초 |
| 3 | 스킬에서 커넥터 사용 선언 | 스킬 수정 시 1줄 추가 |

3단계면 끝이에요. 기술적인 설정은 하나도 없습니다.

그리고 여기서 한 가지 더. 목록에 없는 서비스도 **MCP(Model Context Protocol)를 통해 커스텀 커넥터로 추가**할 수 있어요. 예를 들어 우리 회사 내부 서비스에 MCP를 만들어서 연결하면, Cowork가 사내 시스템 데이터까지 직접 읽고 쓸 수 있게 되는 거죠. 활용도가 훨씬 높아집니다.

### 워크플로우에서의 역할

인플루언서 리서치 파이프라인에서 Google Sheets 커넥터는 두 가지 역할을 해요.

**1) 중복 체크** — 스킬이 검색한 인플루언서가 이미 리스트에 있는지 시트에서 확인합니다. 이전에 연락했던 사람을 또 리스트업하는 실수를 막아주죠.

**2) 자동 등록** — 중복이 아닌 신규 인플루언서를 시트의 다음 행에 자동으로 추가합니다. 이름, 핸들, 팔로워 수, 콘텐츠 요약까지 한 번에요.

### 커넥터 없이 vs 있을 때

| 항목 | 커넥터 없이 | 커넥터 있을 때 |
| --- | --- | --- |
| **결과 저장** | Claude 대화창에서 복붙 | Google Sheets에 자동 기록 |
| **중복 체크** | 시트 열어서 눈으로 비교 | 자동 대조 후 신규만 추가 |
| **히스토리** | 대화 기록에 묻힘 | 시트에 날짜별 누적 |

커넥터 하나 연결하는 데 1분도 안 걸리는데, 이게 있고 없고의 차이가 이렇게 크더라고요.

## 5. Chrome 연동 — 브라우저가 필요한 작업 자동화

인플루언서 리서치에서 한 가지 더 필요한 게 있었어요. 검색으로 찾은 인플루언서의 **실제 프로필을 방문해서 최신 콘텐츠를 확인**하는 거예요. API만으로는 한계가 있는 작업이거든요.

Chrome 연동을 켜면 Cowork가 브라우저를 직접 조작할 수 있어요. 프로필 페이지에 방문해서 최근 게시물을 확인하고, 팔로워 수를 가져오고, 필요하면 스크린샷도 찍어줍니다.

### Chrome 연동 설정

왼쪽 사이드바에서 **사용자 지정 → 커넥터 → Claude in Chrome**을 연결하면 돼요. Chrome 확장 프로그램을 설치하라는 안내가 나오는데, 설치 후 Cowork와 자동으로 연결됩니다.

### 워크플로우에서의 역할

스킬이 검색한 인플루언서 목록을 받아서, Chrome이 각 프로필을 방문하고 아래 정보를 수집해요.

- 팔로워 수 (정확한 최신 수치)
- 최근 게시물 3~5개의 주제
- 콘텐츠 스타일 (사진 위주? 영상 위주? 릴스?)
- 바이오에 협업 관련 키워드가 있는지

Chrome 연동의 핵심 가치는 **API가 없는 서비스의 정보도 가져올 수 있다**는 거예요. 인스타그램처럼 공식 API 접근이 제한적인 서비스도 Chrome으로 직접 방문하면 최신 정보를 수집할 수 있거든요.

## 6. 플러그인 — 스킬만으로 부족할 때

스킬만으로도 충분한 경우가 많지만, 한계가 있는 순간이 있어요.

스킬은 기본적으로 **Claude가 대화 안에서 처리하는 단일 작업**이에요. 그런데 실제 업무 파이프라인은 여러 단계가 엮여 있잖아요. 검색하고, 검증하고, 저장하고, 알림 보내고 — 이걸 스킬 하나에 다 넣으면 복잡해지고, 중간에 하나가 실패하면 전체가 멈춰버리거든요.

플러그인은 이 문제를 해결해요. **스킬 + 커넥터 + 서브에이전트를 하나의 패키지로 묶어서**, 각 단계가 독립적으로 동작하면서도 전체가 하나의 워크플로우로 연결되는 구조예요.

| | 스킬 | 플러그인 |
| --- | --- | --- |
| **구조** | 단일 작업 | 여러 스킬 + 커넥터 패키지 |
| **커넥터** | 별도 설정 필요 | 설치 시 자동 연결 |
| **공유** | 스킬만 공유 | 워크플로우 전체 공유 |
| **에러 처리** | 하나 실패 → 전체 중단 | 단계별 독립 실행 |

### 언제 플러그인을 쓸까?

**팀에 배포할 때** — 스킬, 커넥터, Chrome을 각각 설정하라고 하면 비개발자분들이 헤맬 수 있어요. 플러그인으로 묶으면 "이거 설치해"로 끝이거든요.

**이미 만들어진 걸 쓰고 싶을 때** — Cowork 마켓플레이스에 다른 사람이 만든 플러그인이 올라와 있어요. "influencer research", "lead generation" 같은 키워드로 검색하면 이미 검증된 워크플로우를 설치만 하면 바로 쓸 수 있죠. 거기서 시작해서 내 업무에 맞게 규칙만 수정하는 것도 좋은 방법이에요.

## 7. 스케줄링 — "매주 월요일 아침에 알아서 돌려줘"

파이프라인이 완성됐으면, 마지막으로 **자동 실행**을 걸어둘 차례예요.

### 설정법

두 가지 방법이 있어요.

**방법 1: 대화창에서** — `/schedule` 명령어를 입력하고 "매주 월요일 오전 9시에 인플루언서 리서치 스킬 실행"이라고 말하면 됩니다.

**방법 2: 사이드바에서** — Skills 탭에서 해당 스킬의 ⋯ 메뉴 → **Schedule**을 클릭하면 반복 주기를 설정할 수 있어요.

### 실전 예시

저는 이렇게 설정해뒀어요.

| 항목 | 설정값 |
| --- | --- |
| **실행 주기** | 매주 월요일 |
| **실행 시간** | 오전 9:00 |
| **스킬** | 인플루언서 리서치 v5 |
| **입력값** | 기본 키워드 세트 (제주 여행, 그룹 투어, 여행 크루) |

스케줄링이 실행되려면 **Cowork Desktop 앱이 열려 있어야 해요**. 완전히 종료하면 스케줄이 동작하지 않습니다. 백그라운드에서 실행 중이기만 하면 되니까, 앱을 최소화해두면 돼요.

## 8. 실전에서 배운 것 — 모든 실수를 스킬 규칙으로 만들어라

이 섹션이 이 글의 핵심이에요. 스킬을 만드는 건 시작에 불과하고, **실전에서 겪는 실수들을 하나하나 규칙으로 추가해나가는 과정**이 진짜 자동화거든요.

인플루언서 리서치 스킬을 처음 만들었을 때는 기본적인 검색과 저장만 했어요. 하지만 5번 정도 실행하면서 매번 새로운 문제가 생겼고, 그때마다 스킬에 규칙을 추가했습니다. 그 과정을 공유할게요.

### 교훈 1: URL을 절대 추측하지 마라

초기 스킬은 인스타그램 핸들로 프로필 URL을 조합했어요. `instagram.com/{핸들}` 이렇게요. 문제는 Claude가 검색 결과에서 핸들을 잘못 추출하는 경우가 있었다는 거예요. "travel_jina"를 "traveljina"로 읽어서 존재하지 않는 프로필로 연결되는 일이 생겼어요.

**추가한 규칙:** "URL은 반드시 검색 결과에서 직접 가져온 링크를 사용할 것. 핸들로 URL을 조합하지 말 것."

### 교훈 2: 이메일은 끝까지 파라

인플루언서 협업 제안을 보내려면 이메일이 필요한데, 바이오에 이메일이 있는 사람도 있고 없는 사람도 있어요. 초기에는 바이오에 없으면 "이메일 없음"으로 기록했거든요. 그런데 알고 보니 대부분의 인플루언서는 링크트리나 비즈니스 문의 페이지에 이메일을 따로 올려놔요.

**추가한 규칙:** "바이오에 이메일이 없으면 1) 링크트리/링크 모음 확인 2) 비즈니스 문의 페이지 확인 3) 최근 협업 게시물의 댓글 확인. 3단계까지 확인 후에도 없으면 '이메일 미확인'으로 기록."

### 교훈 3: 플랫폼 핸들을 섞지 마라

인스타그램 핸들이 `@travel_joy`인 사람의 유튜브 채널이 `TravelJoyKR`일 수 있어요. 초기 스킬은 같은 사람인데 다른 플랫폼 핸들을 별도 인물로 등록하는 실수를 했어요.

**추가한 규칙:** "같은 인물의 여러 플랫폼 계정은 하나의 행에 기록할 것. 인스타그램 핸들, 유튜브 채널명, 블로그 URL을 각각의 컬럼에 분리 기록."

### 교훈 4: Chrome이 안 될 때를 대비하라

Chrome 연동으로 프로필을 방문하다가 로그인 팝업이 뜨거나, 봇 감지에 걸리는 경우가 있어요. 이때 스킬이 멈춰버리면 전체 파이프라인이 중단되거든요.

**추가한 규칙:** "Chrome 접근이 실패하면 API 기반 대체 방법으로 전환할 것. 대체 방법도 실패하면 해당 인플루언서를 '수동 확인 필요'로 표시하고 다음으로 넘어갈 것."

### 교훈 5: 하나씩 등록하지 말고 배치로 검증하라

처음에는 인플루언서를 찾을 때마다 바로 시트에 등록했어요. 그랬더니 중간에 기준이 바뀌면 (예: 팔로워 기준을 3천에서 1천으로 낮추면) 이미 등록된 데이터와 일관성이 없어지더라고요.

**추가한 규칙:** "모든 인플루언서를 먼저 임시 리스트에 모으고, 전체 기준으로 한 번에 검증한 뒤, 통과한 항목만 시트에 배치 등록할 것."

### 교훈 6: 모든 실수를 스킬의 규칙으로 만들어라

위의 5가지 교훈이 결국 하나로 귀결돼요. **실수가 생기면 그 실수를 스킬의 규칙으로 추가하는 것**. 사람이라면 "아, 다음엔 조심해야지"로 끝나는 일을, 스킬에 규칙으로 적어두면 **같은 실수가 구조적으로 반복되지 않아요**.

### 스킬 버전 변화

| 버전 | 업데이트 계기 | 추가된 규칙 |
| --- | --- | --- |
| v1 | 최초 생성 | 기본 검색 + 시트 저장 |
| v2 | URL 오류 발견 | URL 직접 추출 규칙 |
| v3 | 이메일 누락 | 이메일 3단계 탐색 규칙 |
| v4 | 핸들 중복 등록 | 멀티 플랫폼 통합 규칙 + 배치 검증 |
| v5 | Chrome 오류 | 대체 방법 폴백 규칙 |

놀라운 건, v1에서 v5까지 하루 만에 업데이트됐다는 거예요. 스킬을 돌려놓고, 그동안 다른 일을 하다가, 결과를 확인하고, 규칙을 추가하고, 다시 돌려놓는 사이클이거든요. 사람이 직접 하면 더 빠를 수도 있어요. 하지만 Cowork의 진짜 장점은 속도가 아니라, **시켜놓고 더 중요한 일을 할 수 있다**는 거예요. 스킬이 돌아가는 동안 나는 다른 업무에 집중하면 되니까요. 지금 v5는 거의 수동 개입 없이 돌아갑니다.

### 스킬의 진화 사이클

이 과정을 정리하면 하나의 순환 구조가 돼요.

```
[아이디어 탭에서 영감 얻기] 다른 사람의 사례 참고
     ↓
[스킬 크리에이터] 내 업무에 맞게 스킬 생성
     ↓
[실행] 스킬 돌려보기
     ↓
[회고] 결과 확인, 문제점 발견
     ↓
[스킬 업데이트] 문제점을 규칙으로 추가 → 다시 실행...
```

매번 프롬프트를 새로 쓰는 게 아니에요. 스킬이라는 **살아있는 문서**를 계속 키워나가는 거예요. 프롬프트는 한 번 쓰면 끝이지만, 스킬은 쓰면 쓸수록 똑똑해집니다.

| **입력** | 키워드, 팔로워 범위 | 포지션, 기술 스택 | 산업, 기업 규모 | 산업, 협업 유형 |
| **처리** | 검색→프로필 확인→중복 체크→등록 | 검색→이력 확인→중복 체크→등록 | 검색→담당자 확인→CRM 체크→등록 | 검색→사업 확인→중복 체크→등록 |
| **출력** | 핸들, 팔로워, 콘텐츠 요약 | 이름, 경력, 기술 매칭도 | 기업명, 담당자, 규모 | 기업명, 사업 영역, 협업 가능성 |
| **커넥터** | Google Sheets | Google Sheets + Gmail | Google Sheets + Slack | Notion + Gmail |

이 템플릿을 그대로 쓰지 마시고, **실행 후 규칙을 추가해나가세요**. v1은 불완전해도 괜찮아요. 중요한 건 v2, v3으로 키워나가는 거니까요.

## 10. 마치며 — 스킬은 만드는 게 끝이 아니라 키우는 게 시작입니다

정리해볼게요.

| 단계 | 도구 | 역할 |
| --- | --- | --- |
| 1 | **스킬 크리에이터** | 반복 업무를 도구로 저장 |
| 2 | **커넥터** | 외부 서비스와 연결 (저장, 알림) |
| 3 | **Chrome 연동** | 브라우저가 필요한 작업 자동화 |
| 4 | **플러그인** | 스킬 + 커넥터를 패키지로 묶기 |
| 5 | **스케줄링** | 자동 반복 실행 |
| 6 | **규칙 추가** | 실수를 구조적으로 방지 |

이 6단계가 하나의 파이프라인으로 엮이면, **1~2시간짜리 반복 업무를 시켜놓고 다른 일에 집중할 수 있게 돼요**.

하지만 이 글에서 가장 전하고 싶었던 건 기능 사용법이 아니에요. **쓰면서 실패하고, 실패를 규칙으로 만들고, 점점 똑똑해지는 과정이 진짜 자동화**라는 거예요. 스킬은 프롬프트와 달리 규칙이 누적되거든요. v1은 실수투성이여도, v5는 거의 사람 손을 안 타요.

물론 모든 걸 자동화에 맡길 수는 없어요. DM이나 이메일을 보내는 것 자체는 자동화할 수 있지만, 이 사람에게 정말 연락할지, 어떤 톤으로 제안할지는 사람이 판단해야 하거든요. 자동화의 역할은 그 판단에 집중할 수 있도록 **반복 작업을 치워주는 것**이에요.

여러분도 가장 반복적인 업무 하나를 골라서 스킬로 만들어보세요. 처음엔 불완전해도 괜찮아요. 쓰면서 키우면 됩니다.
