# joy-blog-writing

조이기술블로그 글의 어조와 흐름을 요즘IT 기사 3편에 맞춥니다. 규칙 본문과 원문 예시는 `references/style-rules.md`에 있습니다. 기계로 판정할 수 있는 항목은 `scripts/check_post.py`가 검사합니다.

## 작업 순서

1. **핵심 주장 정하기**: 이 글이 독자에게 남길 주장을 한 문장으로 적습니다. 이 문장이 리드의 굵은 문장이 되고, 마무리에서 다시 꺼낼 문장이 됩니다.
2. **개요 잡기**: 아래 구조 템플릿에 맞춰 개요를 잡습니다. 소제목은 각 섹션의 결론 문장으로 씁니다.
3. **초안 쓰기**: `references/style-rules.md`의 A(어조), B(문맥 흐름), C(워딩) 규칙을 따릅니다.
4. **흐름 점검**: 아래 판단 체크리스트로 섹션 경계마다 이어받는 문장이 있는지 확인합니다.
5. **AI 티 점검**: humanize-korean을 fast mode, genre `blog`로 돌립니다.
   - **joy-blog-writing 규칙이 humanize 처방보다 우선합니다.** 다음 처방은 적용하지 않습니다.
     - `quick-rules.md` I-1(`~것이다` 결말): `~것입니다`와 `~것이죠` 결말 모두에 적용하지 않습니다.
     - A-10, G-2(유보 표현을 단언으로 바꿈): 추정·한계 표현은 그대로 둡니다.
     - E-7(경어법 혼용): 자리별 해요체를 허용합니다.
     - E-2(`~다` 종결 다양화): 합니다체를 유지합니다.
   - 수치, 고유명사, 인라인 코드는 바꾸지 않습니다. 반영한 수정 이후에도 6단계를 통과해야 합니다.
6. **기계 검사**: 이 스킬 폴더의 `scripts/check_post.py`를 실행합니다(`python3 <스킬 폴더>/scripts/check_post.py <post.md>`).
   - 이미 발행된 글을 고칠 때는 `--baseline <git-rev>`를 붙여 수치·frontmatter·이미지·인라인 코드·표가 보존됐는지도 확인합니다.
   - 사용자가 일부 내용을 빼라고 했다면 `--allow-removal`을 붙입니다. 숫자·인라인 코드·이미지 줄·표 행이 빠지는 것은 허용하고, baseline에 없던 값이 새로 생기면 계속 FAIL로 잡습니다. 다만 집합 비교라서 baseline에 이미 있는 다른 값으로 바꾼 경우(예: 21→18, 18이 다른 곳에 있을 때)는 잡지 못합니다. 그래서 뺀 항목과 남은 수치는 수치 대조표에서 문장 단위로 확인하고, 뺀 항목은 '의도적 삭제'로 적습니다.
   - 링크 URL(`](…)` 안)의 숫자는 수치 주장이 아니므로 N1에서 세지 않습니다(예: GitHub 이슈 번호).
   - exit 0이 나와야 다음 단계로 갑니다.
7. **커밋**: 사용자가 글을 읽고 확인하면 `Post: …` 메시지로 커밋합니다.

## 구조 템플릿

```markdown
---
emoji: 🧑🏻‍💻
title: <검색되는 주제 — 독자가 품을 질문이나 결과>
date: 'YYYY-MM-DD HH:mm:ss'
author: 조이
tags: <공백으로 구분>
categories: 개발
thumbnail: './thumbnail.png'
---

> <독자가 아는 상황 또는 질문>. <어긋나는 지점>.
>
> **<핵심 주장 한 문장>** <이 글에서 다룰 것>.

## <섹션 결론을 담은 합니다체 문장>

<주장 → 사례·수치 → 원인 → 해결>
<마지막 문장: 다음 섹션이 이어받을 핵심어나 질문>

## <…>

## <팁 섹션: 독자가 할 일. 여기서는 ~세요를 씁니다>

## <한계를 밝히는 결론 문장: 측정하지 않은 것은 부정문으로>

## 마치며

<리드의 핵심 주장을 다시 꺼냄> <실천 제안>
```

- 글 끝에 끝인사(🙏), `<br/>`, 댓글 유도, AI 도움 고지를 넣지 않습니다.
- 팁 섹션과 한계 섹션은 다룰 내용이 있을 때만 둡니다.

## 체크리스트

**기계 판정** (`check_post.py`가 판정합니다)

| id | 항목 |
|---|---|
| T1 | 허용하지 않은 요 종결이 없습니다 |
| T2 | 요·죠 종결이 20% 이하입니다 |
| P1 | 문단이 5문장 이하입니다 |
| B1 | 섹션당 굵게가 1개 이하입니다 |
| B2 | 깨지는 굵게가 없습니다 |
| E1 | 금지 문구가 없습니다 |
| L1 | `>` 리드로 시작합니다 |
| H1 | 마지막 섹션이 `마치며`입니다 |
| N1·F1·I1·C1·TB1 | `--baseline`을 줬을 때 숫자, frontmatter, 이미지 줄, 인라인 코드, 표가 보존됐습니다 |

**사람 판정** (괄호 안은 `references/style-rules.md`의 규칙 번호입니다)
- [ ] 섹션 첫 문장이 주장이나 쟁점입니다. 질문으로 열었다면 바로 다음 문장이 답합니다(style-rules B1).
- [ ] 모든 섹션 경계에서 앞 섹션의 핵심어나 질문을 다음 섹션 첫 문장이 이어받습니다. 경계마다 그 문장을 짚을 수 있어야 합니다(style-rules B2).
- [ ] 수치가 주장 바로 뒤에 근거로 붙어 있고, 대상·조건·유보 표현이 원래 측정과 같습니다. "두 도구", "한 번" 같은 한글 수사도 함께 확인합니다(style-rules B3, B5).
- [ ] 같은 접속어가 연달아 나오지 않고, 문두 `그래서`는 세 번 이하입니다(style-rules B4).
- [ ] 추정은 완곡하게, 측정하지 않은 것은 부정문으로 적었습니다(style-rules B5).
- [ ] 마무리가 리드의 주장을 다시 꺼내고 실천 제안으로 닫힙니다(style-rules B6).
- [ ] 약어·단위·지표는 처음 나올 때 괄호로 풀이했습니다(style-rules C5).
- [ ] 소제목이 결론 문장이나 질문입니다(style-rules C7).
